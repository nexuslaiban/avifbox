# AVIFBox — a deploy tells IndexNow which pages it changed

Date: 2026-11-16 · Source: Cloudflare's request log and a search on 2026-11-16. Five days after
launch Bing lists no page of the site (`site:avifbox.com` finds nothing), and its crawler last came
on 2026-11-13. Builds on the six earlier specs; AC numbers continue from them (AC-01…51 are unchanged
unless listed under "Existing behaviour changed").

## Change

1. **The site carries an IndexNow key** (AC-52). IndexNow is the protocol by which a site tells search
   engines that a page is new or has changed, instead of waiting to be crawled. Bing, Yandex, Naver,
   Seznam, Yep and Amazon take part and pass what they are told to each other. Google does not.
2. **`pnpm run deploy` tells IndexNow which pages the deploy changed** (AC-53…AC-56). Before the
   upload it notes the pages whose HTML on the live site is not the build's; after the live check it
   sends that note. A note that was not sent is kept, and the next deploy sends it with its own.

Out of scope: Google (it has no such protocol for ordinary pages; asking for a page to be indexed
stays a click in Search Console), reading Bing's or Google's reports through their APIs, telling
IndexNow of a page that was removed, `lastmod` for every page of the sitemap.

## Existing behaviour changed

- **AC-47 is amended.** `pnpm run deploy` gains two steps: `pnpm indexnow before` after the E2E run
  and ahead of the upload, and `pnpm indexnow after` behind the live check. The chain is still joined
  by `&&` and nothing else.
- A deploy whose upload and live check passed can now end with exit code 1: when IndexNow could not
  be told. The message says that the site is deployed and what IndexNow answered.
- The site serves one more file, `/<key>.txt`, holding the key. It is public by design: it is how a
  search engine checks that a notice comes from the site it names.
- `scripts/verify-live.ts` reads the build and asks the site through `scripts/deployed.ts`, which the
  new command shares. What it checks is unchanged.

## Acceptance criteria

`U` = Vitest, `O` = observed and recorded below.

- **AC-52** (U) `public/` holds exactly one IndexNow key file at its root: `<key>.txt`, where the key
  is 32 hexadecimal characters and is also the file's whole content.
- **AC-53** (U) Given a build and a live site, the pages to tell IndexNow of are: every page of the
  build's sitemap, when the site does not serve the build's key file with the key in it (a site that
  has not shown its key has told IndexNow nothing); otherwise exactly the pages of the sitemap that
  the site does not answer with status 200 and the build's bytes — a page that differs, a page
  answered with another status (even with the build's bytes), a page whose request gets no answer.
  Pages in the order of the sitemap. A site that serves the build as it is gives an empty list. The
  404 page is never among them. A build without a key file, with more than one, or with no page in
  its sitemap is an error that says which.
- **AC-54** (U) Telling IndexNow of a list of pages is one `POST` to
  `https://api.indexnow.org/indexnow` with `Content-Type: application/json; charset=utf-8` and a body
  holding `host`, `key`, `keyLocation` (the key file's address) and `urlList`. The answers 200 and 202
  pass, with a message that names how many pages and the answer. Any other answer, and a request that
  gets no answer, is an error that names the status and, for 400, 403, 422 and 429, what the protocol
  says it means. An empty list sends nothing and passes, saying so. A list holding an address that is
  not a page of the build's sitemap sends nothing and is an error that names the address.
- **AC-55** (U, O) In `package.json`, `deploy` runs `pnpm indexnow before` between the E2E run and
  `wrangler deploy`, and `pnpm indexnow after` behind `pnpm verify:live` (U). The first deploy with
  the key tells IndexNow of all thirteen pages and IndexNow answers 200 or 202; `pnpm indexnow before`,
  run again afterwards, finds no page to tell (O).
- **AC-56** (U) The pages IndexNow is owed before an upload are those noted earlier and not yet sent
  together with those the upload changes: each once, in the order of the build's sitemap. A noted
  address that is no longer a page of the build's sitemap is dropped. With nothing noted earlier they
  are the pages the upload changes; when the upload changes nothing they are the pages noted earlier.

## Decisions worth recording

- **Only the pages a deploy changed, not the sitemap every time.** The protocol's FAQ: "It is not
  designed for submitting every URL on your site at once", and "Avoid submitting the same URL many
  times a day unless there are meaningful content changes." It accepts all of a site's addresses
  after a site-wide change.
- **"Changed" is the HTML the site serves, compared byte for byte with the build**, as the live check
  compares. A new stylesheet name changes every page; that is a site-wide change.
- **Which pages changed can only be seen before the upload**, so the command has two halves and a
  note between them. One command wrapped around the upload would hide `wrangler deploy` and the live
  check from the chain AC-47 reads.
- **The note is what IndexNow is still owed, not what one run found.** A deploy that stops between
  the upload and the notice (the live check fails, the run is interrupted) leaves pages that changed
  and were not told. The run after it sees a site that already serves the build and finds no page, so
  a note written anew would lose them for good. `before` therefore adds to the note, and only a
  notice that IndexNow accepted removes it. A note can name a page whose upload never happened;
  telling IndexNow of it once does no harm.
- **The note is `.indexnow-owed.json` at the root of the repository, ignored by git.** The system's
  temporary folder is emptied by a restart and shared by every checkout of the repository.
- **No key on the site yet means every page is news.** That makes the first deploy send all thirteen
  pages without a third mode to run by hand. A new key does the same.
- **`after` fails when nothing was noted**, and passes when the note is empty. A missing note means
  `before` did not run; an empty one means no page changed.
- **It fails loudly, at the end, and does not retry.** The site is live by then, and the message says
  so. `pnpm indexnow after` can be run again, and the next deploy sends the note if nobody does.
- **`api.indexnow.org`, not Bing's own address.** Any engine that takes part passes a notice on to the
  others.
- **The key file is found, not named.** It is the one `.txt` at the root of the build whose content is
  its own name, so the key is written down once, in `public/`.

## Approval

Approved by the owner on 2026-11-16 as "a key file, the thirteen pages pushed to Bing, and every
deploy pushing by itself". Sending only the pages a deploy changed was decided afterwards, on reading
the protocol's FAQ. Committed to `main` once its tests are green, then deployed with
`pnpm run deploy`.
